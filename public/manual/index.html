    pose6d — User Guide

    pose6d finds objects in a camera image and reports their full 6D pose (position and orientation) so a robot arm can pick them. You teach it a new object by labeling a few images, it trains a keypoint-detection network, and from then on it detects every instance of that object live and streams the poses to the robot over TCP/IP.

    This guide explains every control in the desktop application: what it does, where its value is stored, the sensible default and when to change it. It also documents the configuration files, the robot communication protocol and the files the application writes.

    Getting started

    Launching the app

    The same application runs in three ways:

    HowCommandUse it for
    From sourcepython main_app.py from the pose6d folder, with the project environment activated (on the development PC: C:\Work\Envs\qtgui)Development, labeling, training
    Deployed exepose6d.exe (built by main_app_deploy.py; entry point main_app_wrapper.py)Production PCs next to the robot
    Web interfacepython -m webapp, then open http://127.0.0.1:5000/ Quick detection tests and remote viewing. No labeling or training.

    Installing from source (Windows):

    python -m venv C:\Work\Envs\qtgui
C:\Work\Envs\qtgui\Scripts\activate.bat
pip install torch torchvision            # or the CUDA build: --index-url https://download.pytorch.org/whl/cu118

    Notepyrealsense2 is only needed for Intel RealSense cameras (D435 / D455 / D580 are the tested models). A plain USB webcam works without it.

    Where data lives

    Everything that belongs to one object lives in one object folder, by default under data\objects\:

    data\objects\bricks-15\
  object_config.json   ← the object's settings: keypoints, camera, detection (see reference)
  images\              ← captured images, plus one <image>.json label file next to each labeled image
  models\              ← trained checkpoints keypoint_group_model_NNNN.pth
  cameras\             ← calibration.json (camera intrinsics)
  results\             ← benchmark / evaluation output
  labels\              ← reserved
  robots\              ← reserved

    Application-wide state that is not tied to an object is kept in main_app_config.json in the pose6d folder: the last selected object, the default camera type, communication addresses. It is machine-local, created on first run, and never shipped.

    Concepts & vocabulary

    TermMeaning
    ObjectOne kind of part the robot should pick, for example a wooden brick. Stored as an object folder.
    Keypoint / target pointA named, distinctive point on the object (a corner, an edge midpoint) with known 3D coordinates in millimetres in the object's own coordinate frame. bricks-15 has 13: corners t1–t4 (top), b1–b4 (bottom), edge midpoints c12 c23 c34 c14 and the top centre tc.
    Object Id (instance)Several copies of the same object can appear in one image. Each copy gets its own id (1, 2, 3 …) when labeling, and detection reports one result per instance.
    LabelThe pixel position of a keypoint on one image, saved in <image>.json.
    ModelThe trained keypoint network, models\keypoint_group_model_NNNN.pth (NNNN = epoch). The highest number is used for detection and for further training.
    PoseWhere the object is relative to the camera: tvec = translation (x, y, z) in millimetres, rvec = rotation as a Rodrigues rotation vector in radians (axis × angle). Computed with PnP from the detected keypoints and their 3D coordinates.
    Quality0–1 score of how well the detected keypoints fit the object model. Closer to 1 is a tighter fit; good detections of the sample object score about 0.97–0.99.
    IntrinsicsThe camera's lens parameters (focal lengths, image centre, distortion), found by camera calibration. Needed for correct poses.
    Hand-eye calibrationFinding where the camera sits relative to the robot flange (camera on the arm), so poses can be converted into robot coordinates.

    Connect the camera, look at the live image, capture images for labeling, and calibrate the camera lens.

    Capturing images

    1. Select the object first (Workflow, step 1). Images are saved into that object's folder.
    2. Set Camera Type, Resolution and Exposure, then click 🟢 Connect Camera. The live image appears on the right and the button turns red (🔴 Disconnect Camera).
    3. Click 🖼️ Save Image for each view. Move the objects and the camera between shots: different positions, angles, lighting and partial occlusions make a more robust model.

    Images are saved as <format>_YYYYMMDD_HHMMSS.png (for example rgb_20261028_141502.png) in the object's images\ folder, or in the folder chosen with Select Image Folder in the calibration panel if you picked one.

    How many images?The sample object bricks-15 was trained from 14 labeled images with several bricks each. Start with 10–20 varied images and add more where detection is weak.

    Camera Calibration

    Computes the camera intrinsics from photos of a printed chessboard (doc\checkerboard_pattern.pdf).

    ControlValuesMeaning / guidance
    Calibration Pattern6x9 7x10 4x11 5x5, or type NxMNumber of inner corners of the chessboard (columns × rows), not squares.
    Square size (mm)10 20 30 50 100 200 300, or type a valueSide of one printed square, measured on the print. It sets the scale of the calibration.
    📁 Select Image FolderFolder with the chessboard photos; they are listed under Images. Click one to view it.
    🛠️ CalibrateRuns the calibration on every image in the folder.
    Expected resultA Calibration Complete message. The camera matrix and distortion are written to the object's object_config.json and to cameras\calibration.json, which detection reads.

    Take 15–25 photos with the board filling different parts of the image and tilted at different angles. An invalid pattern or square size shows Bad Pattern / Bad Square Size; too few usable images show Calibration Failed.

    🖊️ Object Teaching

    Mark where each keypoint is on your images, check the labels with overlays, and train the model.

    Controls

    ControlWhat it does
    🖱️ Select ObjectSwitches to another object folder. Shows Invalid Object if the folder has no valid object_config.json.
    Object IdInstance number 1–20 you are labeling. Each instance is drawn in its own color. Label every visible copy of the object in an image with a different id.
    ❌ Delete ObjectRemoves all points of the selected Object Id from the current image.
    Target PointsThe object's keypoints with their 3D coordinates in mm. The selected point is the one the next click places. Double-click a point to rename it or change its X/Y/Z. That changes the object model for all images, not the label on this image.
    📁 Select Image FolderFolder whose images appear in the Images list (default: the object's images\).
    ImagesClick to load. Labeled images (with a saved .json) are shown in green.
    🗑️ Clear PointsRemoves all points from the current image (not saved until Save Points).
    💾 Save PointsWrites the points to <image>.json next to the image and turns the image green.
    📐 Show AxisComputes each instance's pose from the labels and draws its coordinate axis (X red, Y green, Z blue).
    🔷 Show ShapeSame, but draws the object's faces (point_faces) as outlines.
    🚀 Train ModelStarts or stops training. See Training.

    Labeling an image

    1. Pick an Object Id (start with 1) and click an image in the Images list.
    2. Click a row in Target Points, or just start: the first point is pre-selected.
    3. Left-click the keypoint's position on the image. A cross and label appear and the selection moves to the next point, so you can click through the whole object in order.
    4. Right-click near a point to delete it.
    5. Repeat with the next Object Id for every other copy of the object in the image.
    6. Click 💾 Save Points.

    Label only points you can actually see; hidden corners are left out. Loading a green image shows its saved points so you can fix them and save again.

    Checking labels with overlays

    Turn on Show Axis or Show Shape after labeling. If the axes sit on the object corners and the outlines match the edges, the labels, the 3D coordinates and the camera calibration agree.

    Nothing drawn for an instance?An instance needs at least 4 labeled points. The overlay is also skipped (with a warning in the log) when the reprojection error is above 5 px, which usually means a mislabeled point, wrong 3D coordinates, or a missing or wrong camera calibration.

    Training

    1. With the labeled object selected, click 🚀 Train Model.
    2. If the object has no model yet, confirm No Model Found → start training?. If a model exists, Model Exists → retrain it? continues from the latest checkpoint instead of starting over.
    3. Training runs in the background; the app stays usable. The button reads 🛑 Stop Training.
    4. To stop early, click it again. You are asked whether to save the model at the current epoch (Save Partial Model).
    SettingWhereDefaultMeaning
    Epochsdetection_parameters.n_epochs100Passes over the training images, for a new run and for each retrain
    Learning ratedetection_parameters.lr0.0001Step size of the optimiser. Leave it unless training diverges.
    Image scaledetection_parameters.image_scale0.5Images are scaled by this before entering the network. Smaller is faster but loses small details.
    Train splitdetection_parameters.train_split0.95Fraction of labeled images used for training; the rest for validation.

    n_epochs and lr are not in a new object_config.json; add them to detection_parameters (Settings tab or a text editor) to change them. Checkpoints are written to models\keypoint_group_model_NNNN.pth.

    Sending results to the robot

    Set Output = TCP/IP Stream and start detection. For every frame, the model runs once and the same result is drawn on screen and stored in the robot server. Each time the robot asks (get results) it receives the newest result. The server keeps running when you stop detection or switch the output back; stop it from the Communication tab.

    📐 Robot Setup

    Hand-eye calibration: finds the camera's position on the robot flange from images of a chessboard taken at known robot poses.

    ControlWhat it does
    🟢 Connect CameraLive view from the camera; enables Save Image.
    Save ImageSaves the current frame as capture_N.jpg (in the folder pose6d was started from) and adds it to the list.
    Calibration MethodIntrinsic · Extrinsic · Hand-Eye. Currently not used: Calibrate System always runs hand-eye calibration.
    Robot ModelHow the three rotation values of a robot pose are read. UR-Euler: Euler angles, R = Rz·Ry·Rx (degrees if any value is above 2π, otherwise radians). All others (UR-RVEC, KUKA, DENSO, ABB, TM, NEURA, DOBOT): rotation vector in radians.
    Image FilesImages in data\robot_calibration\. Selecting one shows it and fills Robot Pose from the dataset file.
    Robot Pose tX tY tZ / rX rY rZRobot flange pose when the selected image was taken (translation in mm, rotation per Robot Model). Display only.

    Calibration dataset

    The images and camera_robot_calibration.json must be in data\robot_calibration\:

    {
  "chessBoardSize": [9, 6],          // inner corners (columns, rows)
  "chessBoardSquareSize": 10.0,      // mm
  "viewInfo": [
    { "imageName": "calib_robot_0001.jpg",
      "robotPose": [142.72, 356.93, -74.27, 0.5825, 3.0991, 0.0186] },   // x y z (mm), r1 r2 r3
    ...
  ]
}

    At least 3 images with a detected chessboard are required; 10–15 views with large rotations between them give a stable result.

    Where is the result?The calibration result (samples used, camera RMS error, camera matrix, distortion, and the camera-to-gripper rotation R_cam2gripper / translation t_cam2gripper) is currently only printed to the console window. It is not shown in the tab or saved.

    Protocol reference

    Each message is a 4-byte big-endian length followed by that many bytes of UTF-8 JSON. The client sends a request and the server answers on the same connection, any number of times.

    RequestResponse result
    {"command": "get results", "params": {}}Latest detection, see below
    {"command": "ping", "params": {}}{"success": true, "message": "pong"}
    anything else{"success": false, "message": "Unknown command: …"}
    { "status": "ok", "command": "get results",
  "result": {
    "success": true,
    "frame_id": 128,                    // increases by 1 per processed frame
    "timestamp": 1793190045.698,        // seconds since 1970 when the frame was processed
    "objects": {
      "1": { "success": true,
             "rvec": [2.2796, -0.6202, -0.0567],   // rotation vector, radians
             "tvec": [-206.12, 118.24, 1553.01],   // translation, mm, camera frame
             "quality": 0.9798 },
      "2": { "success": false, "rvec": null, "tvec": null, "quality": 0.0 }
    } } }
    FieldMeaning
    statusok, or error with a message if the server failed to handle the request
    frame_idSame number in two answers means no new frame was processed in between
    objectsOne entry per detected instance, keyed by instance number
    success (object)false when too few keypoints were found to compute a pose; skip that entry
    rvec / tvecObject pose in the camera frame (see concepts). Convert with the hand-eye result for robot coordinates.
    quality0–1 fit score; reject low values (for example below 0.9) in the robot program

    A minimal robot-side client in Python:

    import json, socket, struct

def request(sock, command):
    payload = json.dumps({"command": command, "params": {}}).encode()
    sock.sendall(struct.pack(">I", len(payload)) + payload)
    size = struct.unpack(">I", sock.recv(4, socket.MSG_WAITALL))[0]
    return json.loads(sock.recv(size, socket.MSG_WAITALL))

with socket.create_connection(("127.0.0.1", 5005)) as s:
    result = request(s, "get results")["result"]
    for obj_id, obj in result["objects"].items():
        if obj["success"] and obj["quality"] > 0.9:
            print(obj_id, obj["tvec"], obj["rvec"])

    ⚙️ Settings

    A form for the active object's object_config.json. The object path is shown at the top; the form reloads when you switch objects.

    Field typeHow to edit
    Number / textType directly. Check boxes for true/false values.
    Short list or matrixOne box per value (e.g. pose, point_coord, intrinsic_matrix).

    Save Configuration checks the values first and saves only if all checks pass:

    • point_names and point_coord have the same number of entries, and every coordinate is [x, y, z];
    • every name in point_faces exists in point_names;
    • every resolution is [width, height];
    • intrinsic_matrix is 3×3.

    Worked examples

    1 · Teach a new object from scratch

    1. Workflow → Create New…: name the object, for example bracket-01.
    2. Settings: replace the placeholder cube with the real keypoints: point_names, point_coord (mm, measured from a corner you choose as origin) and point_faces. Save Configuration.
    3. Camera Setup: connect the camera and calibrate it with 15–25 chessboard images.
    4. Camera Setup: Save Image 15–20 varied views of one or more parts.
    5. Object Teaching: label every visible part (one Object Id per part), Save Points per image, and check with Show Axis.
    6. Object Teaching → Train Model. When it finishes, test in Validation with Source = Directory on the same images, then with Source = Camera.
    7. Where detection is weak, capture and label more images of those situations and click Train Model again (retrain continues from the last checkpoint).

    2 · Soak-test detection on a folder

    Validation → Source = Directory, Detector ON, Show Axis ON → Detect… → choose the folder. The images repeat until you press Stop. Use it to watch for unstable or missing detections over many cycles without a camera.

    3 · Stream poses to a robot

    1. Validation: Source = Camera, Output = TCP/IP Stream, Detect…. The server starts on 127.0.0.1:5005.
    2. For a robot on another machine: stop detection, set the server address in Communication (the PC's network IP), Server Start, then start detection again.
    3. Check with the built-in client: Communication → Client Start, Command = get results, Repeat every 1000 ms. Results appear in the lower monitor.
    4. Program the robot to send get results whenever it is ready to pick (see protocol), and to skip objects with success: false or low quality.

    4 · Hand-eye calibration

    1. Fix the chessboard in the cell. Move the robot (camera on the flange) to 10–15 different poses that look at the board from different angles.
    2. At each pose save an image into data\robot_calibration\ and write its file name and robot pose into camera_robot_calibration.json.
    3. Robot Setup: choose the Robot Model that matches how your controller reports rotations, check a few images (the pose fields show what was read), then Calibrate System.
    4. Read the result in the console. A camera RMS error under 1 px indicates good images.

    Troubleshooting

    SymptomLikely cause → fix
    Camera connects but the image stays black / "Failed to acquire an image"Some Windows camera drivers open the camera but never deliver frames through the default backend. pose6d tests for this and retries with DirectShow automatically; if it still fails, close other programs using the camera and try another cameraid.
    Nothing is detectedDetector OFF; wrong object selected; object partly outside the image; model trained on too few or too different images. Turn on Show Heatmap (source mode) to see whether the model finds keypoints at all.
    Some instances have no axisFewer than 4 keypoints were found for them (log: Object N has K keypoints (need >= 4)). Add training images with similar views or occlusions.
    Axes are drawn but in the wrong placeCamera not calibrated, or calibrated at another resolution; wrong point_coord. Recalibrate and check Show Shape in Object Teaching.
    Show Axis draws nothing in Object TeachingUnder 4 labeled points, or reprojection error above 5 px: a point is labeled with the wrong name or the 3D coordinates are wrong.
    Server does not start (port in use?)Another program, or a second pose6d, is using the port. Choose another port or close the other program.
    Client receives the same frame_id every timeDetection is not running, or Output is not TCP/IP Stream.
    Communication tab is greyed outNo license with the robot-communication feature and the 1-hour grace period has ended. Activate a license with feature 0x0004.
    Settings: Validation ErrorThe message lists the rule that failed (see Settings), most often point_names and point_coord with different counts.
    Training is very slowTraining runs on the CPU without a CUDA build of PyTorch. Install the CUDA build, or lower image_scale.
